# 招聘执行规则（本机自定义层模板）

> 复制到工作区后可自由修改。本文件是**产品 config 覆盖不到的偏好**的落脚点：
> 遍历顺序、话术风格、重复投递口径、待确认清单等。
>
> **数值一律不要写在这里**——时间窗、每日/每轮上限、冷却分钟数统一由 `config.json` 的
> `schedule` 字段控制，并在运行时读取。写在文档里会和配置漂移，是真实踩过的坑。
>
> 每条规则后标注 `（YYYY-MM-DD 用户明确）`，用于消解后续覆盖关系；被推翻的条目请标注
> `~~删除线~~ 已被 YYYY-MM-DD 决定覆盖`，而不是直接删掉——保留来龙去脉便于排查。

---

## 一、执行档位

- 主动找岗：`mode_discover = semi | favorite | auto`（见 `config show`）
- 消息答疑：`mode_reply = semi | auto`
- 任何外发前必须逐条过 `pro guard-reply` / `pro evaluate-job`；返回 `ok:false`、
  `downgraded:true`、`handoff_required:true` 一律停手，不得绕过。

## 二、必须先经本人确认才能发的内容

以下内容**只拟草稿**，等本人明确回复「发」后才可发送。**即使本人正在讨论同一话题，
未看到「发」字也不得抢先发送**——一次抢发可能直接烧掉一个机会，违反此条比漏发严重。

1. 离职原因、对前东家的任何评价；
2. 期望薪资、上家薪资构成、薪资底线、几薪；
3. 个人/家庭/婚育/年龄/住址等隐私；
4. 面试时间、地点、改约、到岗承诺；
5. 任何需要「本人立场」的解释、表态、道歉、拒绝；
6. 本人正在改话术、尚未拍板的任何句子。

> 例外需单独写明，例如：「对方请求交换微信/手机号时，只要岗位不明显不匹配，可直接
> 同意并同步给本人」（（YYYY-MM-DD）用户明确）。

## 三、话术风格

1. 对方主动打招呼时**不复述岗位**、不写「看到XX岗，想进一步聊聊」；直接回应对方的点，
   2–3 句平实结束。
2. 对方索要简历时，同意/发出即可，不补「简历发您了，方便时看下」这类无用信息。
3. 少客套、少波浪号、不用表情；不重复对方刚说过的话，不复述 JD 原文。
4. 对 HR/招聘专员：最短路径先答硬指标；对业务负责人：给具体案例与数字。
5. 收尾用「好的，谢谢」「好的，麻烦了」这类短确认。
6. 收到拒信也必须回一句「好的，谢谢」礼貌结束，不许静默不回复。

## 四、收藏与批量投递

- 非工作时间（夜间、周末）只点「感兴趣」收藏，**不发任何消息**；
- 收藏岗落入 `favorite-batch`，`apply_at` 之前**严禁投递**（由 `gate` 代码层强制）；
- 到点后逐条串行投递，`channel` 记 `favorite_queue`（不占当日筛选投递额度）；
- 岗位下线 / 已投过 / 已被拒 → `--outcome skipped` 并写明原因。

## 五、重复投递口径（（YYYY-MM-DD）用户明确）

- 投过但**对方没有回复** → 可以再跟一次（同岗位一天最多再跟一次，避免刷屏）；
- 对方**明确回复不合适/拒绝** → 不再重复投递，直接归档；
- 三维查重命中不等于一律跳过，需核对是否为同岗位、同版本简历、同时期动作。

## 六、筛选放宽与收紧（（YYYY-MM-DD）用户明确）

- 公司规模、是否「企业级 AI」、是否属于目标行业 → **不作为硬门槛**，方向与薪资合适即可；
- 硬门槛只有：薪资下限 ≥ `min_salary_k`、非外包/驻场/派遣、职能方向相关；
- 特殊岗位类型需按 JD 实质判断，不能按标题一刀切（例如 FDE：偏产品定义/客户方案可投，
  要求自己写代码/懂底层架构则不投；拿不准交本人确认）。

## 七、找岗遍历顺序（（YYYY-MM-DD）用户明确，含二次刷新）

推荐流前两页 → **刷新再看前两页** → 求职期望①前两页 → **刷新再看** →
求职期望②前两页 → **刷新再看** → 其他关键词 → 换城市。

每级内部：卡片级初筛（薪资/城市/外包/前东家/未重复）→ 进详情读完整 JD →
`ledger check-dup` + `pro evaluate-job` → 通过才开场。

## 八、已知的坑（写下来避免重复踩）

- 岗位长 JD 被折叠时，必须先展开并滚到「工作地址/公司介绍」，否则地点核验会漏判；
- 标题写 A 城市、JD 写 `base B` 这类矛盾，以正文实际标注为准，直接跳过；
- 「现场调研 / 深入业务现场 / FDE」是正常研发用词，不要误判为驻场外派；
- 聊天页顶部已绑定职位时，先自己点开读 JD，**严禁向 HR 索要“具体职责/JD”**。
